# 本体に保存する照明送信エラー

照明ジョブの送信失敗時だけ、CoreS3のNVS（不揮発領域）に直近20件を保存する。
成功時は書き込まず、21件目から古い順に上書きする。再起動・通常のファームウェア書き込みで保持される。フラッシュ全消去では失われる。

## USBで確認

接続ごとにポートを調べ、115200 baudのシリアルモニターで `errorlog` と入力してEnterを押す。

```sh
.venv/bin/pio device list
.venv/bin/pio device monitor --port <確認したポート> --baud 115200
```

`ERROR_LOG_BEGIN` から `ERROR_LOG_END` までが古い順の一覧。コマンドは読み取りのみで記録を削除しない。

- `seq`：保存順。
- `time`：失敗した送信を開始した時点のUTC Unix秒。NTP未同期なら0。
- `uptime_ms`：同時点の起動後ミリ秒（約49.7日で一周）。
- `route`：local / cloud。
- `device`：0=キッチン、1=リビング。
- `signal`：0=電源巡回、1=明るく、2=暗く、3=点灯、4=消灯、5=常夜灯、6=暖かく、7=白く、8=全灯、9=普段。
- `code`：HTTP結果または負の通信エラー。-11=応答待ち時間切れ。
- `elapsed_ms`：失敗した送信処理の所要時間。
- `gap_ms`：共通ワーカーで直前の送信処理が終了してから今回を開始するまで。起動後最初の送信は-1。赤外線の実測間隔ではない。
- `rssi`：送信開始時のWi-Fi電波強度（dBm）、未接続なら0。
- `completed`：ジョブ内で成功した数 / 全送信数。

Wi-Fi認証情報、トークン、ホスト、URL、送信データ、HTTP応答本文は保存しない。ボタン受付前の入力・設定チェックの通知は対象外。

保存はジョブの失敗結果をメインループで受け取った時点で行う。その前に電源が切れたエラーや、保存自体が失敗した場合は残らない。保存失敗はUSBに `ERROR_LOG: save failed` 等を出力し、照明信号は再送しない。

## 開発時の確認

```sh
c++ -std=c++17 -I tests/error_log_stubs -I include tests/error_log_test.cpp -o /tmp/cores3-error-log-test
/tmp/cores3-error-log-test
```

NVSとUSBを模擬し、成功時の非保存、20件上限・並び順、揮発状態の初期化後の復元、保存失敗、不完全な記録、長すぎるコマンドを検証する。実機の電源断・再起動による保持確認とは区別する。
