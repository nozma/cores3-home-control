# Nature Remo ローカルAPIの長押し検証

検証日：2026-10-28。対象：リビング照明 Panasonic HH-CG2033A。

## 結果

- 対象Remo（ファームウェア `Remo/1.0.69-gbbcc0de`）へのローカル接続に成功。
- 純正リモコンの「暗く」の長押しから、同じ40ビットのフレームが繰り返されることを確認。
- 取得した完全なフレームと間隔を使い、5フレーム・約0.56秒分をPOSTするとHTTP 200。
- この再送で照明が暗くなったことをユーザーが確認。長押し相当の信号をローカルAPIで送信できることを確認した。
- 20フレーム・約2.6秒分を1リクエストにするとHTTP 400。正確な上限は未特定。大きなデータを一括送信せず、小さい塊に分割する。
- 同じ5フレームの塊を、信号同士が重ならない間隔で6回送信し、全6件でHTTP 200を確認。合計30フレームを約4秒間で送信でき、さらに暗くなったこともユーザーが確認した。

## APIとデータ

- Bonjourの `_remo._tcp` で探索し、クラウドに登録された対象RemoのMACアドレスと照合した。
- `GET /messages` で直近の受信信号を取得する。受信信号がない場合は404になることがあった。
- `POST /messages` へ `format`・`freq`・`data` を含むJSONを送る。
- `X-Requested-With: XMLHttpRequest` が必要。POSTには `Content-Type: application/json` を付ける。
- 取得した長押し信号は `format=us`、`freq=36`。完全な1フレームは83個の時間値で構成される。
- フレーム間の休止は `[65535, 0, 9592]` マイクロ秒だった。長い休止を単一の65535超の値へ変換せず、取得した並びを維持した。
- 検証済みの5フレーム送信データは427個の時間値、JSONは1826バイト。
- 長押しのGET応答は2839バイトで途中切れになり、不完全なJSONになった。完全なJSONとして扱わず、繰り返しが一致した完全なフレームのみを再送に使用した。

## 保存場所と次の実装

- 取得した信号と再送用データはGit管理外の `.local/remo-ir/` に保存した。
- `dim-hold-5frames.json` がユーザー確認済みの再送データ。
- 「明るく」「暖かく」「白く」も純正リモコンの長押しから採取した。白くのデータは途中に欠損フレームがあったため、その後の一致する完全なフレーム対から復元した。
- `tools/remo_ir_capture.py` は途中切れや欠損を考慮し、一致する完全なフレーム対と休止間隔だけを採用する。
- `tools/remo_ir_generate.py` は4方向の5フレームデータを検証し、Git管理外の `include/remo_local.h` を生成する。各データは約0.56〜0.57秒、1826〜1836バイト。
- CoreS3のリビング調光・調色ボタンにローカル送信を組み込んだ。タッチ継続中に短い塊を送信し、前の送信時間＋80msが経過してから次を送る。指を離す・ボタン外へ動かす・タブ変更などで未送信ジョブを無効化する。通信失敗時は自動再送しない。
- CoreS3への組み込みはビルド・テスト済み。4方向の見た目の変化と指を離した際の停止は実機確認が必要。
- 長押し時間と明るさ％の対応や絶対位置は未確認。連続送信ができても％指定が正確になるわけではない。

仕様：[Nature Remo Local API](https://local-swagger.nature.global/)

## 推定％指定への変更

- ユーザーの計測では明るさ・色とも約5セットで端に達するため、1セットを推定20%とする。
- 画面の長押し操作は削除し、両軸それぞれ0/20/40/60/80/100%ボタンを追加した。
- 推定値がある場合は0%・100%も含め差分セット数だけ送り、同じ値なら送信しない。未確認の場合だけ近い端へ5セット送ってから指定位置へ移動する。到達音が繰り返し鳴らないよう、既知の位置から余分な送信をしない。
- 明るさ0%は最小点灯、消灯は別操作。色0%は暖色側、100%は白色側。
- 全灯の成功で明るさ100%に更新する。普段で両軸は保存設定に戻るため未確認にする。
- この％は調整範囲内の推定位置であり、実際の光量やKelvinの線形な割合ではない。
- 状態遷移テストで明るさ・色の全指定値を検証。実機ログでも明るさ100%の6セット、100%→40%の差分3セット、0%の6セット送信成功を確認した。0%完了後もAPI上の電源はONであり、最小点灯と消灯を区別している。
- 明るさ・色ともCoreS3の画面から20%刻みで操作できることをユーザーが実機で確認した。
